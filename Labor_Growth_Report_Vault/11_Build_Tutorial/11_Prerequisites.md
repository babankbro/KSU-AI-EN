## Prompt A · สร้างข้อมูลในวอลต์

```text
เขียน 03_OBE_PLO_Design_2570/08_Study_Plan_and_Dependencies.md

ตารางความสัมพันธ์ระหว่างรายวิชา
คอลัมน์: รหัสวิชา | ชนิดความสัมพันธ์ | รหัสวิชาที่อ้างถึง | เหตุผลเชิงวิชาการ

ชนิดความสัมพันธ์มี 3 แบบเท่านั้น
  hard   วิชาบังคับก่อน  ต้องผ่านก่อนจึงลงเรียนได้ → ต้องอยู่ภาคก่อนหน้าเท่านั้น
  weak   วิชาแนะนำก่อน   ควรผ่านมาก่อนแต่ไม่บังคับ
  coreq  วิชาเรียนคู่     เรียนพร้อมกันได้ → อยู่ภาคเดียวกันได้

กฎที่ต้องยึด
- ห้ามใส่ hard ให้วิชาที่อยู่ภาคเดียวกัน ถ้าต้องเรียนคู่กันให้ใช้ coreq
- ห้ามใส่ hard เกินความจำเป็น เพราะทำให้นักศึกษาตกค้าง
  ถ้าเป็นเพียง "ควรรู้มาก่อน" ให้ใช้ weak
- วิชาบรรยายกับวิชาปฏิบัติการชุดเดียวกันให้ใช้ coreq
- คอลัมน์เหตุผลต้องเขียนว่า "ต้องใช้ความรู้เรื่องอะไรจากวิชานั้น"
  ไม่ใช่ "เป็นวิชาพื้นฐาน" ซึ่งไม่ได้บอกอะไร

ปิดท้ายด้วยสรุปจำนวนความสัมพันธ์แยกตามชนิด
```

> [!tip] ทำไมต้องแยก hard กับ weak
> ปัญหาคลาสสิกคือใส่วิชาบังคับก่อนไปหมดจนนักศึกษาที่ตกวิชาเดียวติดล็อกทั้งสาย
> การแยก **บังคับ** ออกจาก **แนะนำ** ทำให้ตอบกรรมการได้ว่าล็อกเฉพาะที่จำเป็นทางวิชาการจริง ๆ

## Prompt B · สร้างกราฟบนเว็บ

```text
1. เพิ่มฟิลด์ใน COURSES ของ src/data.js
   h: [รหัส] วิชาบังคับก่อน · w: [รหัส] แนะนำก่อน · co: [รหัส] เรียนคู่

2. เขียนฟังก์ชันตรวจความถูกต้องใน data.js และเรียกใช้ตอน import
   - ความสัมพันธ์ hard ที่วิชาต้นทางอยู่ภาคเดียวกันหรือหลังกว่า → console.error พร้อมชี้คู่นั้น
   - รหัสใน h/w/co ที่ไม่มีอยู่จริงใน COURSES → console.error
   - วงจรย้อนกลับ (A ต้องก่อน B และ B ต้องก่อน A) → console.error

3. สร้าง src/DependencyGraph.jsx
   - ใช้ dagre จัด layout แล้ววาด SVG เอง ไม่ใช้ React Flow
     เหตุผล: dagre เป็น layered layout ที่จัดโหนดเป็นชั้นโดยไม่ทับกัน
     และคืน bend points ของทุกเส้น จึงวาดเส้นอ้อมกล่องได้จริง ไม่ทับชื่อวิชา
   - rankdir "LR" จัดชั้นตามภาคการศึกษา
   - เส้นสามแบบต้องแยกกันด้วยสายตา
       hard  เส้นทึบมีหัวลูกศร
       weak  เส้นประ
       coreq เส้นทึบบางไม่มีหัวลูกศร
   - มีคำอธิบายสัญลักษณ์บนหน้า

4. โหมดการแสดงผล 3 โหมด สลับด้วยปุ่ม
   dependencies  ระบายสีตามชั้นปี
   group         ระบายสีตามกลุ่มวิชา
   plo           ระบายสีตาม PLO ที่รายวิชารับผิดชอบ

5. คลิกโหนดแล้วไป /courses/:code

6. เขียนสคริปต์ตรวจว่าไม่มีโหนดทับกันในทุกโหมด แล้วพิมพ์ผลตอน build
```
