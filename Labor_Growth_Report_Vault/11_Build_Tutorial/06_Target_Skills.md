# ขั้นที่ 6 · ทักษะเป้าหมาย HS · SS · EF

> **เป้าหมาย: ยุบทักษะหลายหมื่นป้ายจากประกาศงานจริง ให้เหลือรายการที่หลักสูตรรับผิดชอบได้จริง**

## ทักษะ 3 ตระกูล และที่มาที่ต่างกัน

| ตระกูล | รหัส | ที่มา | ใครเป็นคนบอกว่าต้องมี |
|---|---|---|---|
| Hard Skills | `HS1–HS20` | นับจาก `classifiedMatches` ในขั้นที่ 5 | **ตลาด** |
| Soft Skills | `SS1–SS10` | นับจาก `classifiedMatches` ในขั้นที่ 5 | **ตลาด** |
| ฐานวิศวกรรม | `EF1–EF6` | ข้อกำหนดวิชาชีพวิศวกรรมและสภาวิชาชีพ | **มาตรฐานวิชาชีพ** |

> [!important] ทำไมต้องมี EF แยกออกมา
> ทักษะที่ตลาดเรียกร้องไม่ครอบคลุมสิ่งที่ทำให้เรียกว่า *วิศวกรรม* — ประกาศงานไม่ค่อยเขียนว่าต้องเขียนแบบหรือคำนวณค่าความปลอดภัยเป็น แต่หลักสูตรวิศวกรรมต้องมี
> ถ้าเอาแต่ตลาดนำจะได้หลักสูตรวิทยาการคอมพิวเตอร์ที่ติดป้ายว่าวิศวกรรม

## Prompt A · สร้างข้อมูลในวอลต์

```text
เขียน 03_OBE_PLO_Design_2570/03_Target_Skills.md
โดยใช้ผลนับทักษะจาก src/jobsIndex.json ที่สร้างในขั้นที่ 5 เป็นหลักฐาน

ตารางที่ 1 — Hard Skills (HS1–HS20)
คอลัมน์: รหัส | ชื่อทักษะ | ขอบเขต | จำนวนประกาศที่พบ | สัดส่วนต่อประกาศทั้งหมด | ระดับตามแนวทาง Bloomเป้าหมาย
เรียงจากจำนวนประกาศมากไปน้อย

ตารางที่ 2 — Soft Skills (SS1–SS10) คอลัมน์เหมือนกัน

ตารางที่ 3 — ฐานวิศวกรรม (EF1–EF6)
คอลัมน์: รหัส | ชื่อทักษะ | ขอบเขต | ที่มาเชิงมาตรฐาน | ระดับตามแนวทาง Bloomเป้าหมาย
ตระกูลนี้ไม่มีคอลัมน์จำนวนประกาศ เพราะไม่ได้มาจากตลาด

ตารางที่ 4 — นิยามระดับตามแนวทาง Bloom
  B1 จำ · B2 เข้าใจ · B3 ประยุกต์ใช้ · B4 วิเคราะห์ · B5 ประเมินค่า · B6 สร้างสรรค์
พร้อมคำอธิบายว่าแต่ละระดับ "ประเมินด้วยอะไร"

หลักการยุบทักษะ
- ทักษะที่เป็นเครื่องมือคนละยี่ห้อแต่ทำงานเดียวกัน ให้ยุบเป็นข้อเดียว
  แล้วใส่ชื่อเครื่องมือไว้ในคอลัมน์ขอบเขต
  เช่น PyTorch/TensorFlow/JAX → "การพัฒนาและฝึกสอนโมเดล ML/DL"
- ทักษะที่พบน้อยกว่า 2% ของประกาศ ไม่ควรขึ้นเป็นทักษะเป้าหมายระดับหลักสูตร
  ให้ไปอยู่ในวิชาเลือกแทน แล้วบันทึกไว้ท้ายไฟล์ว่าตัดออกเพราะอะไร
- จำนวน HS ไม่ควรเกิน 20 ข้อ เพราะเกินกว่านั้นจะออกแบบชุดทักษะไม่ได้

ปิดท้ายด้วย
- ตารางทักษะที่พบในตลาดแต่ตัดออก พร้อมเหตุผล
- ตารางทักษะที่หลักสูตรใส่เพิ่มเองแม้ตลาดยังไม่เรียกร้อง พร้อมเหตุผล
  (มักเป็นทักษะกลุ่มธรรมาภิบาลและความปลอดภัย ที่ตลาดจะเรียกร้องในอีก 2–3 ปี)
```

> [!tip] ช่อง "ตัดออกเพราะอะไร" คือช่องที่กรรมการชอบที่สุด
> มันแสดงว่าเราอ่านข้อมูลจริงและ **ตัดสินใจ** ไม่ใช่แค่คัดลอกอันดับทักษะยอดนิยมมาแปะ

## Prompt B · สร้างหน้าเว็บ

```text
1. เพิ่มใน src/obeData.js
   HARD_SKILLS            = [{ id, name, scope, jobs, pct, level }]
   SOFT_SKILLS            = [{ id, name, scope, jobs, pct, level }]
   ENGINEERING_FOUNDATIONS= [{ id, name, scope, standard, level }]
   LEVELS                 = { B1..B6: { label, assess } }

2. เพิ่มส่วน ④ id="skill" ในหน้า src/pages/Obe.jsx
   - ตาราง 3 ตระกูล มีตัวกรองตามตระกูลและระดับตามแนวทาง Bloom
   - ทักษะที่มาจากตลาด ให้แสดงแถบสัดส่วนและจำนวนประกาศข้างชื่อ
     คลิกแล้วไป /jobs พร้อมกรองทักษะนั้นไว้ให้เลย
   - ทักษะ EF ให้แสดงป้าย "ข้อกำหนดวิชาชีพ" แทนแถบสัดส่วน
     เพื่อให้เห็นชัดว่าคนละที่มา
   - ส่วน "รายวิชาที่สอนทักษะนี้" แสดงป้าย "รอเชื่อมรายวิชา — ขั้นที่ 14"

3. เพิ่มรหัส HS/SS/EF และ B1–B6 เข้าทะเบียน codeInfo.js

4. แถบตรวจ: ทักษะที่ยังไม่มีระดับตามแนวทาง Bloomเป้าหมาย
```

- [ ] ทุก HS/SS มีจำนวนประกาศที่พบ อ้างกลับไปที่หน้า `/jobs` ได้
- [ ] ทุก EF มีที่มาเชิงมาตรฐานระบุไว้
- [ ] ทุกทักษะมีระดับตามแนวทาง Bloomเป้าหมาย
- [ ] มีตารางทักษะที่ตัดออกพร้อมเหตุผล ไม่ใช่รายการที่คัดมาแล้วอย่างเดียว
