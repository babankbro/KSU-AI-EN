# ส่วนขยาย A · แผนภาพสายธารความเชื่อมโยง (Alluvial Diagram)

> **ทำหลังจบขั้นที่ 15 — เพราะแผนภาพนี้กินข้อมูลจากทุกขั้นตั้งแต่ผู้มีส่วนได้ส่วนเสียถึงรหัส KSA**

## แผนภาพนี้ตอบอะไรที่ตารางตอบไม่ได้

หน้า `/obe` มีตารางเชื่อมโยงหลายชุด แต่ตารางตอบไม่ได้ว่า **"เสียงของใครไหลไปจบที่ไหน"**
แผนภาพสายธารทำให้เห็นการไหลเป็นเส้นที่ความหนาบอกน้ำหนัก และเห็นทันทีว่าโหนดไหนไม่มีเส้นเข้าหรือออก — ซึ่งคือช่องว่างของหลักสูตร

## 6 มุมมองที่ต้องมี

| รหัส | คอลัมน์ | ตอบคำถาม | ใช้ข้อมูลจากขั้น |
|---|---|---|---|
| `v1` | ผู้มีส่วนได้ส่วนเสีย → แหล่งหลักฐาน → Need → ชุดทักษะ | เสียงของใคร ผ่านหลักฐานอะไร กลายเป็นความต้องการข้อไหน | 2 · 7 |
| `v2` | Need → ชุดทักษะ → กลุ่มรายวิชา | ความต้องการถูกแปลงเป็นทักษะ แล้วลงเรียนที่กลุ่มไหน | 2 · 7 · 9 |
| `v3` | ทักษะเป้าหมาย → ชุดทักษะ → ทักษะย่อย + ระดับ | HS/SS/EF เชื่อมเข้า AISK และลึกถึง L1–L4 | 6 · 7 |
| `v4` | PLO → กลุ่มรายวิชา (CLO) → มิติ K–S–A | ผลลัพธ์หลักสูตรกระจายสู่รายวิชาและแตกเป็นสามมิติ | 4 · 8 · 14 |
| `v5` | ทักษะ → ชุดทักษะ → PLO → KSA | ทักษะแต่ละตัวรองรับ PLO ใด และปรากฏใน KSA ข้อไหน | 6 · 7 · 8 |
| `v6` | PLO → มิติ K–S–A → รหัส K/S/A รายข้อ | ลงถึงรหัสรายข้อ — เส้นหนา = ข้อนั้นถูกใช้ในกี่ PLO | 4 · 8 |

## Prompt · สร้างแผนภาพสายธาร

```text
สร้างแผนภาพสายธาร (Alluvial / Sankey) บนหน้า /obe ของเว็บ curriculum-graph

1. สร้าง src/alluvialViews.js
   export const VIEWS = [{ id, name, desc, build }]
   โดย build() คืน { nodes, links, cols }
     nodes = [{ id, col, label, sub?, color? }]
     links = [{ from, to, value }]
     cols  = [{ key, label }]   ลำดับคอลัมน์จากซ้ายไปขวา
   ข้อมูลต้นทาง import จาก obeData.js / data.js / ksaData.js / courseKsaData.js เท่านั้น
   ห้ามพิมพ์โหนดหรือเส้นด้วยมือ ทุกโหนดต้องคำนวณจากข้อมูลจริง
   สร้าง 6 มุมมองตามตารางในเอกสารนี้

2. สร้าง src/Alluvial.jsx เป็นคอมโพเนนต์ทั่วไปที่รับ { nodes, links, cols }
   - วาดด้วย SVG เอง ไม่ใช้ไลบรารีชาร์ต
   - คำนวณตำแหน่งแนวตั้งของโหนดในแต่ละคอลัมน์จากผลรวมน้ำหนักของเส้นที่ต่ออยู่
     แล้วเรียงโหนดเพื่อลดการไขว้ของเส้นให้น้อยที่สุด
   - เส้นวาดด้วย path แบบ cubic bezier ความหนาแปรตาม value
     โปร่งใสประมาณ 0.35 และเข้มขึ้นเมื่อ hover
   - hover ที่โหนด → ไฮไลต์เฉพาะเส้นที่ผ่านโหนดนั้น "ตลอดสาย" ทั้งต้นทางและปลายทาง
     ไม่ใช่เฉพาะเส้นที่ติดกับโหนด · เส้นที่ไม่เกี่ยวให้จางลง
   - คลิกโหนดที่เป็นรหัส (PLO, AISK, K/S/A) → ไปหน้ารายละเอียดของรหัสนั้น
   - แสดงหัวคอลัมน์จาก cols และจำนวนโหนดในแต่ละคอลัมน์

3. เพิ่มในหน้า pages/Obe.jsx
   - ปุ่มสลับมุมมอง v1–v6 พร้อมคำอธิบายสั้นของมุมมองที่เลือก
   - ใต้แผนภาพแสดง "โหนดที่ไม่มีเส้นเข้า" และ "โหนดที่ไม่มีเส้นออก"
     เพราะนี่คือช่องว่างของหลักสูตรที่ต้องอธิบายให้ได้

4. ข้อกำหนดด้านการแสดงผล
   - โหนดต้องไม่ทับกัน ตรวจด้วยสคริปต์แล้วรายงานตอน build
   - ป้ายชื่อยาวให้ตัดด้วย ellipsis และแสดงเต็มใน tooltip
   - บนจอเล็กกว่า 900px ให้เลื่อนแผนภาพในแนวนอนได้ภายในกรอบของตัวเอง
     ห้ามให้ทั้งหน้าเลื่อนแนวนอน
   - ใส่ปุ่มดาวน์โหลด SVG
```

## เกณฑ์ตรวจรับ

- [ ] ทั้ง 6 มุมมองไม่มีโหนดทับกัน
- [ ] hover ที่โหนดใดก็ได้แล้วไฮไลต์สายครบทั้งซ้ายและขวา
- [ ] รายการ "โหนดที่ไม่มีเส้นเข้า/ออก" ตรงกับผลตรวจในขั้นที่ 2–14
- [ ] บนจอ 375px แผนภาพเลื่อนได้ในกรอบ และหน้าไม่เลื่อนแนวนอน

> [!tip] วิธีใช้แผนภาพนี้ตอนนำเสนอ
> **อย่าเปิดมุมมองรวมทั้งหมดตั้งแต่แรก** ให้เปิด `v1` แล้วชี้สายเดียวจากผู้มีส่วนได้ส่วนเสียหนึ่งกลุ่ม
> เล่าให้จบสายก่อน แล้วค่อยเปิดสายอื่น มิฉะนั้นผู้ฟังจะเห็นแค่เส้นพันกันแล้วปิดสมอง
