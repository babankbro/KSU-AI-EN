## Prompt A · สร้างข้อมูลในวอลต์

```text
เขียน 05_TQF2_Academic_Drafts/10_Course_Learning_Outcomes_CLO_Mapping.md

หนึ่งหัวข้อต่อหนึ่งรายวิชา รูปแบบตายตัว เพราะสคริปต์ parse ด้วยตำแหน่งคอลัมน์

### <รหัสวิชา> <ชื่อวิชา>

| CLO | YLO | PLO/ระดับ | KSEC–AISK | หลักฐาน |
|---|---|---|---|---|
| CLO1 <ข้อความที่วัดได้> | YLO1.1 | PLO2 (I) | K5, K17 · S1, S14 · E2, C1; AISK02/03 | <หลักฐานการประเมิน> |

ตำแหน่งคอลัมน์ที่สคริปต์ใช้ ห้ามสลับ
  1 = CLO<เลข> ตามด้วยข้อความ
  2 = Sub-YLO ที่ป้อนเข้า (หลายข้อคั่นด้วย /)
  3 = PLO พร้อมระดับในวงเล็บ
  4 = รหัส KSEC เรียง K · S · E · C คั่นด้วย · แล้วตามด้วย ; AISK..
  5 = หลักฐานการประเมิน

หลักการเขียน CLO
- ขึ้นต้นด้วยคำกริยาที่วัดได้ ลงท้ายด้วย "ได้"
- ระบุระดับ Bloom ให้ทุก CLO โดยดูบริบทของโจทย์ ไม่ใช่ดูคำกริยา
  คำว่า "ออกแบบ" อยู่ได้ทั้ง B3 ถึง B6 — ตามมาตรฐานที่กำหนด = B3 · เลือกให้เหมาะกับเงื่อนไข = B4
  กำหนดเกณฑ์แล้วตัดสิน = B5 · นิยามข้อกำหนดเองจากโจทย์เปิด = B6
- เพดานตามชั้นปี: ปี 1 = B2–B3 · ปี 2 = B3–B4 · ปี 3–4 = B4–B5 (โครงงานและสหกิจถึง B6)
- หนึ่ง CLO = หนึ่งชิ้นหลักฐานที่ให้คะแนนได้จริง ไม่ใช่หัวข้อการสอน
- 2–4 CLO ต่อรายวิชา ถ้าเกินแสดงว่าซอยละเอียดเกินจนประเมินไม่ไหว
- ระดับ I/R/M ต้องสอดคล้องกับเมทริกซ์ YLO จากขั้นที่ 13
- หลักฐานต้องเป็นสิ่งที่เก็บได้จริง ไม่ใช่ "นักศึกษาเข้าใจ"

กฎการใส่รหัส KSEC — สำคัญที่สุดของขั้นนี้
- หนึ่ง CLO ใส่ได้ไม่เกิน "มิติละ 2 รหัส" สำหรับ K และ S
  ส่วน E กับ C รวมกันไม่เกิน 2 รหัส เพื่อคงเพดานรวม 6 รหัสเท่าเดิมหลังแยกเป็น 4 มิติ
  ยกเว้น CLO ที่ประกาศตั้งแต่ 3 PLO ขึ้นไป หรือกรณีที่ต้องรองรับ PLO ที่ประกาศไว้ ให้ K ได้ถึง 3
- เกณฑ์คัดเลือก
  (1) เลือกรหัสที่ตรงกับคำกริยาและหลักฐานของ CLO นั้นก่อน
  (2) ทุก PLO ที่ CLO ประกาศ ต้องมี K หรือ S รองรับอย่างน้อยหนึ่งรหัส
      ไม่ปล่อยให้เหลือแต่จริยธรรมหรือลักษณะบุคคล
  (3) ไม่ใส่รหัสซ้ำข้าม CLO ในวิชาเดียวกัน ให้แต่ละ CLO มีเจ้าภาพชัด
  (4) หลักฐานต้องตรง — ถ้าหลักฐานคือ "ชุดแบบ" ห้ามใส่รหัสที่ต้องวัดด้วย peer assessment

ข้อบังคับ
- รหัสวิชาห้ามซ้ำในเอกสารนี้ หัวข้อที่ซ้ำจะถูกสคริปต์เขียนทับและ CLO หายเงียบ ๆ
- วิชาชีพเลือกไม่ต้องเขียน CLO ให้ใช้การอนุมานผ่านชุดทักษะแทน
- ปิดท้ายด้วยจำนวนรายวิชาและจำนวน CLO ที่เขียนได้
```

> [!danger] กับดักที่ทำให้ข้อมูลเสียหายจริง
> ตอนใส่รหัส KSEC แบบไม่จำกัดจำนวน ระบบจริงเคยมี CLO เดียวอ้าง **K 21 รหัส S 15 รหัส** พร้อมกัน
> ซึ่งบอกผู้ตรวจไม่ได้เลยว่าวิชานั้นประเมินอะไร และทำให้รหัสหลุดไปอยู่บน CLO ที่ไม่เกี่ยว
> เช่นวิชาเขียนแบบถือรหัส "พัฒนาซอฟต์แวร์ปัญญาประดิษฐ์" **ให้ใส่เพดานตั้งแต่วันแรก**

## Prompt B · สร้างสคริปต์และหน้า CLO

```text
1. สร้าง src/cloData.js
   CLO_LIST = [{ code, name, clos: [{ n, text, ylo: [], plo: [{ id, level }],
                                      evidence, aisk: [] }] }]

2. สร้าง scripts/build-mapping-md.mjs   (npm run build:mapping)
   สร้าง 3 ไฟล์กลับเข้าวอลต์
     08_TQF2_Book_Revisions/15_Section4_5_Curriculum_Mapping.md
       ตารางรายวิชา × PLO ค่าในช่อง = ระดับสูงสุดของ CLO ในรายวิชานั้น
     08_TQF2_Book_Revisions/16_Section4_6_CLO_Mapping.md
       ตาราง CLO × PLO ราย CLO พร้อมระดับ
     08_TQF2_Book_Revisions/17_Section4_7_Skill_Set_Coverage.md
       ตารางชุดทักษะ × รายวิชา — เติมหนี้ที่เว้นไว้ในขั้นที่ 7
   พิมพ์สรุป: จำนวนวิชาบังคับ วิชาเลือก และยืนยันว่ามี CLO ครบทุกวิชาบังคับ

3. สร้าง scripts/build-course-ksa.mjs   (ต่อท้าย npm run build:ksa)
   - อ่าน 10_CLO_Mapping.md + 18_KSEC_Codebook.md + 17_Section4_7_Skill_Set_Coverage.md
   - normalise line ending ทุกไฟล์ก่อนเสมอ
   - วิชาบังคับ: ใช้รหัส KSEC ที่ระบุตรงในตาราง CLO
   - วิชาชีพเลือก: ไม่มี CLO จึงอนุมานผ่าน AISK → KSEC จากส่วนที่ 6 ของสมุดรหัส
     แล้ว "คัดเหลือมิติละไม่เกิน 2" โดยจัดอันดับจาก
       (ก) ชื่อวิชาใกล้กับนิยาม/ขอบเขตของรหัสแค่ไหน — น้ำหนักสูงสุด
       (ข) รหัสนั้นปรากฏในกี่ชุดทักษะของวิชานั้น
       (ค) อยู่ในชุดทักษะแรกที่ระบุไว้
       (ง) เสมอกันเรียงตามเลขรหัส เพื่อให้ผลคงที่ทุกครั้งที่ build
     ติดป้าย derivedFrom: "aisk" และหน้าเว็บต้องแสดงคำว่า "อนุมานจากชุดทักษะ"
   - ตรวจรหัสวิชาซ้ำ ถ้าเจอให้ throw error
   - เขียน src/courseKsaData.js และ 05_TQF2_Academic_Drafts/19_Course_and_CLO_KSEC_Tables.md

4. หน้า src/pages/Clo.jsx (/clo) แบ่งส่วนตาม navConfig
   - 4.6 Curriculum Mapping: ตารางรายวิชา × PLO จัดกลุ่มตามชั้นปีและภาค
   - 4.7 CLO Roll-up: แต่ละ PLO มีรายวิชาและ CLO ใดรับผิดชอบ ไปถึงระดับใด
   - CLO ที่ป้อนเข้าแต่ละ Sub-YLO
   - การกระจายรายวิชาสู่ชุดทักษะ แยกชุดเจ้าภาพหลักออกจากชุดสนับสนุน
   - CLO และ K–S–E–C รายวิชา: การ์ดรายวิชาพร้อม CLO และรหัส KSA ทุกข้อ

5. เติมส่วนที่เว้นไว้ในขั้นก่อนหน้า
   /plo และ /plo/:id  → รายวิชาที่รับผิดชอบ แยก host / support
   /obe ⑤             → รายวิชาที่รองรับแต่ละชุดทักษะ
   /obe ④             → รายวิชาที่สอนแต่ละทักษะ
   /courses/:code     → CLO/PLO/KSEC ของรายวิชานั้น

6. แถบตรวจบนหน้า /clo
   - Sub-YLO ที่ไม่มี CLO รองรับ
   - PLO ที่ไม่มี CLO ของวิชาบังคับไปถึง M
   - CLO ที่เกินเพดานรหัส KSEC
   - CLO ที่ประกาศ PLO แต่ไม่มี K หรือ S รองรับ
```

> [!warning] ลำดับการรันที่ห้ามสลับ
> `build-course-ksa.mjs` อ่านไฟล์ `17_Section4_7_Skill_Set_Coverage.md` ที่ `build:mapping` เป็นคนเขียน
> ถ้ารัน `build:ksa` ก่อน `build:mapping` จะได้ข้อมูลของ **รอบที่แล้ว** โดยไม่มีข้อความเตือนใด ๆ
> ```bash
> npm run sync:curriculum && npm run build:mapping && npm run build:plan && npm run build:ksa
> ```

## หนี้ที่ชำระคืนในขั้นนี้

- ✅ รายวิชาที่รับผิดชอบแต่ละ PLO (เว้นจากขั้นที่ 4)
- ✅ รายวิชาที่รองรับแต่ละชุดทักษะ ตาราง 4.7 (เว้นจากขั้นที่ 7)
- ✅ รายวิชาที่สอนแต่ละทักษะ (เว้นจากขั้นที่ 6)

## เกณฑ์ตรวจรับ

- [ ] ทุกรายวิชาบังคับมี CLO อย่างน้อย 2 ข้อ
- [ ] ทุก Sub-YLO มี CLO ป้อนเข้าอย่างน้อยหนึ่งข้อ
- [ ] ทุก PLO มี CLO ของวิชาบังคับที่ไปถึง M
- [ ] ไม่มี CLO ใดเกินมิติละ 2 ยกเว้นข้อยกเว้น K=3 ที่ประกาศ ≥3 PLO
- [ ] วิชาชีพเลือกทุกวิชามีไม่เกิน 6 รหัส และขึ้นป้าย "อนุมานจากชุดทักษะ"
- [ ] แก้ CLO หนึ่งข้อในวอลต์ → ตาราง 4.5, 4.6, 4.7 และหน้าเว็บเปลี่ยนพร้อมกัน
