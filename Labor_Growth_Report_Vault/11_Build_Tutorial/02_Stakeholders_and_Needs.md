## Prompt A · สร้างข้อมูลในวอลต์

```text
เขียน 03_OBE_PLO_Design_2570/01_Stakeholder_Needs.md

ตารางที่ 1 — ผู้มีส่วนได้ส่วนเสีย
คอลัมน์: รหัส | กลุ่ม | วิธีเก็บข้อมูล | ขนาดกลุ่มตัวอย่าง | ช่วงเวลาที่เก็บ | ระดับความสำคัญ
ใช้รหัส SH1–SH8 ครอบคลุมอย่างน้อย
  ผู้ประกอบการ · ศิษย์เก่า · นักศึกษาปัจจุบัน · ผู้ปกครอง · อาจารย์ผู้สอน
  หน่วยงานภาครัฐในพื้นที่ · สภาวิชาชีพ · ครูแนะแนวโรงเรียนมัธยม

ตารางที่ 2 — ความต้องการ
คอลัมน์: รหัส | ข้อความความต้องการ | ระดับความสำคัญ | ผู้มีส่วนได้ส่วนเสียที่ระบุ (SH ใดบ้าง) | ที่มา
ใช้รหัส N1–N18

หลักการเขียนความต้องการ
- เขียนเป็น "สิ่งที่บัณฑิตต้องทำได้" หรือ "ปัญหาที่ต้องแก้" ไม่ใช่ชื่อวิชา
  ผิด : "ต้องการให้เปิดวิชา Machine Learning"
  ถูก : "ต้องการบัณฑิตที่นำโมเดลขึ้นใช้งานจริงและดูแลหลังใช้งานได้"
- ห้ามเขียนความต้องการที่ไม่มี SH ใดรองรับ
  ถ้ามาจากรายงานแนวโน้มหรือนโยบายชาติ ให้ระบุแหล่งอ้างอิงในคอลัมน์ที่มาแทน
  และแยกให้ชัดว่าเป็น "เสียงจากผู้มีส่วนได้ส่วนเสีย" หรือ "หลักฐานเชิงเอกสาร"

ปิดท้ายด้วย
- จำนวน SH และ N ที่เขียนได้
- รายการ SH ที่ยังไม่มีความต้องการใดผูกอยู่ (ถ้ามี ต้องอธิบายว่าทำไมจึงเก็บกลุ่มนี้ไว้)
```

> [!important] "ขนาดกลุ่มตัวอย่าง" คือช่องที่ห้ามเว้น
> คำถามแรกของผู้ตรวจคือ *ถามใคร กี่คน เมื่อไร* ถ้าตอบไม่ได้ ความต้องการทั้ง 18 ข้อจะกลายเป็นความเห็นของผู้เขียนเล่มทันที
> ถ้ายังไม่ได้เก็บข้อมูลจริง ให้เขียนว่า `รอเก็บข้อมูล` อย่าใส่ตัวเลขที่ยังไม่มี

## Prompt B · สร้างหน้าเว็บ

```text
1. สร้าง src/obeData.js พร้อมคอมเมนต์บนสุดว่าซิงก์มาจากไฟล์ไหนในวอลต์
   STAKEHOLDERS = [{ id, name, method, n, period, prio }]
   NEEDS        = [{ id, text, level, sh: [รหัส SH], source }]
   PRIO_INFO    = { [ระดับ]: { label, color } }
   NEED_LEVEL   = { [ระดับ]: { label, color } }

2. หน้า src/pages/Obe.jsx — สร้างโครงหน้าที่จะเติมไปเรื่อย ๆ จนถึงขั้นที่ 14
   ส่วน ① id="sh"    ตารางผู้มีส่วนได้ส่วนเสีย แสดงขนาดกลุ่มตัวอย่างเป็นตัวเลขเด่น
   ส่วน ② id="needs" การ์ดความต้องการ N1–N18 ระบายสีตามระดับความสำคัญ
                     แต่ละการ์ดแสดงป้าย SH ที่ระบุความต้องการนั้น
   ผูก section id ให้ตรงกับ sections ใน navConfig.js เพื่อให้ sidebar เลื่อนไปถูกจุด

3. แถบตรวจบนหน้า
   - SH ที่ไม่มีความต้องการใดผูกอยู่
   - ความต้องการที่ไม่มี SH ใดรองรับ
   ถ้าไม่มีปัญหาให้แสดงแถบเขียว

4. สร้าง src/codeInfo.js เป็นทะเบียนคำอธิบายรหัสย่อ และ src/CodeTip.jsx
   - ใช้ event delegation จุดเดียวใน App.jsx จึงครอบคลุมทุกหน้าโดยไม่ต้องแก้ทีละจุด
   - ชี้ค้างที่ป้าย SH3 หรือ N7 ที่ไหนก็ได้ในเว็บ แล้วขึ้นคำอธิบายเต็ม
   - ดึงข้อมูลจาก obeData.js ไม่เก็บซ้ำ
   - ปิดด้วยเมาส์ออก เลื่อนหน้าจอ หรือ Esc · ปิดอัตโนมัติบนจอเล็กกว่า 560px
   ทะเบียนนี้จะขยายเพิ่มทุกขั้นตั้งแต่นี้ไป
```

## เกณฑ์ตรวจรับ

- [ ] ทุก N มี SH หรือแหล่งอ้างอิงเชิงเอกสารรองรับ
- [ ] ทุก SH มีขนาดกลุ่มตัวอย่างและช่วงเวลาที่เก็บ
- [ ] ชี้ค้างที่ป้าย `N7` แล้วขึ้นคำอธิบายเต็ม
- [ ] ไม่มีความต้องการข้อใดเขียนเป็นชื่อวิชา
