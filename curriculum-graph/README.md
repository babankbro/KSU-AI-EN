## ป๊อปอัปคำอธิบายรหัสย่อ (ทุกหน้า)

ชี้ค้างที่ป้ายรหัสใดก็ได้ในเว็บ — **PLO1–7 · YLO1–4 และ Sub-YLO · AISK01–09 · G1–G7 · N1–N18 · SH1–SH8 · GA1–GA5 · H1–H20 · S1–S10 · L1–L4 · ระดับ I/R/M · รหัสรายวิชา · อาชีพ C01–C17** — จะแสดงคำอธิบายฉบับเต็มพร้อมข้อมูลประกอบและลิงก์ไปหน้ารายละเอียด

- `src/codeInfo.js` เป็นทะเบียนคำอธิบาย (ดึงจาก `data.js` / `obeData.js` / `cloData.js` ไม่ซ้ำข้อมูล) · `src/CodeTip.jsx` แสดงป๊อปอัปด้วย event delegation จุดเดียวใน `App.jsx` จึงครอบคลุมทุกหน้าโดยไม่ต้องแก้ทีละจุด
- อ่านรหัสจากข้อความของป้าย (หรือ `data-tip` เมื่อป้ายแสดงข้อความย่อ เช่น โหนดในกราฟ) · ปิดด้วยการเลื่อนเมาส์ออก เลื่อนหน้าจอ หรือกด `Esc`
- ปิดอัตโนมัติบนจอเล็กกว่า 560px และอุปกรณ์สัมผัส · ในหน้า `/courses` ไม่ซ้อนกับป๊อปอัปคำอธิบายรายวิชาของการ์ด

ป๊อปอัปในหน้า `/courses` เปิดหลังชี้ค้าง 180 มิลลิวินาที วางตัวข้างการ์ดโดยเลือกฝั่งที่มีที่ว่าง เลื่อนอ่านภายในได้
ปิดด้วยการเลื่อนเมาส์ออกหรือกด `Esc` และปิดอัตโนมัติบนจอเล็กกว่า 860px หรืออุปกรณ์สัมผัส (ใช้แตะเข้าหน้ารายละเอียดแทน)

## เครื่องมือวาดกราฟ

ใช้ **[dagre](https://github.com/dagrejs/dagre) + SVG ที่วาดเอง** (ไม่ใช้ React Flow) เพราะ

- dagre เป็น **layered graph layout** — จัดกล่องเป็นชั้นโดย **ไม่ทับกัน** และเรียงในแต่ละชั้นเพื่อ **ลดการไขว้ของเส้นให้น้อยที่สุด**
- dagre คืน **bend points ของทุกเส้น** → วาดเส้นตามจุดหักจริง ทำให้ **เส้นเดินอ้อม ไม่ทับกล่อง/ป้ายชื่อวิชา**
- ตรวจสอบแล้ว: **node overlap = 0 ทุกโหมด**

## ฟอนต์

ใช้ **IBM Plex Sans Thai** (ไทย–อังกฤษ) และ **IBM Plex Mono** (รหัสวิชา) โหลดจาก Google Fonts ใน `index.html` — กำหนดผ่านตัวแปร `--font-sans` / `--font-mono` ใน `src/styles.css` · หากใช้งานออฟไลน์จะถอยไปใช้ Noto Sans Thai / Segoe UI ตามลำดับ

## วิธีรัน (ต้องมี Node.js ≥ 18)

```bash
cd curriculum-graph
npm install
npm run sync:curriculum
npm run dev        # เปิด http://localhost:5173
```

Build เป็นไฟล์สแตติก

```bash
npm run build      # ได้โฟลเดอร์ dist/
npm run preview
```

## Deploy บน Vercel

repo นี้มีเว็บอยู่ในโฟลเดอร์ย่อย จึงต้องตั้ง **Root Directory**

1. [vercel.com/new](https://vercel.com/new) → Import repository `KSU-AI-EN`
2. **Root Directory** → Edit → เลือก `curriculum-graph`
3. Framework จะขึ้น **Vite** เอง (Build `npm run build` · Output `dist`)
4. Deploy

`vercel.json` ในโฟลเดอร์นี้ตั้ง **rewrites** ให้ทุก path กลับไปที่ `index.html` แล้ว — จำเป็นสำหรับ client-side routing ไม่เช่นนั้นการเปิด `/plo/3` ตรง ๆ หรือกด refresh จะได้ 404

> ตั้ง **Ignored Build Step** เป็น `git diff --quiet HEAD^ HEAD ./` เพื่อไม่ build ใหม่เมื่อ commit แตะเฉพาะไฟล์ใน vault

## หมายเหตุข้อมูล

- โครงสร้างข้อเสนอใหม่รวม **133 นก.**: Core Track 9 วิชา/27 นก. และวิชาเลือกชีพ 5 วิชา/15 นก.
- แผนการเรียนข้อเสนอปัจจุบันกระจาย 19–19–19–19–19–16–16–6 รวม **133 นก.** โดยใช้รหัสรายวิชาตามชั้นปีล่าสุด
- ตรวจแล้วว่า **ไม่มีรายวิชาใดมีวิชาบังคับก่อนอยู่ในภาคเรียนเดียวกันหรือหลังกว่า** — ความสัมพันธ์ที่อยู่ภาคเดียวกันถูกกำหนดเป็น co-requisite
- กราฟ Dependencies แสดงวิชาแกนและวิชาชีพบังคับครบตามแผน รวม EN-132-201 และ EN-132-302–309
- วิชาเลือกชีพไล่รหัสครบ **48 วิชา** — กลุ่ม 1 `EN-135-301–315` · กลุ่ม 2 `EN-135-316–333` · กลุ่ม 3 `EN-135-334–348`
- ถ้อยคำ PLO ยกมาตามต้นฉบับ `04_PLOs_7_OBE.md` ซึ่งขึ้นต้นด้วยคำกริยาโดยตรง โดยมีประโยคนำร่วมกันว่า
  “เมื่อสำเร็จการศึกษา ผู้เรียนสามารถแสดงผลลัพธ์การเรียนรู้ระดับหลักสูตรได้ดังต่อไปนี้” แสดงไว้เหนือรายการ PLO
- กลุ่มย่อยของ `ge` / `eng` / `proj` / `field` / `elec` มาจากข้อกำหนดของหลักสูตร
  ส่วน `ai` และ `track` จัดกลุ่มตามภาคการศึกษาในแผนการเรียน (ระบุกำกับไว้ในหน้า)
- คำอธิบายภาษาอังกฤษซิงก์จาก Vault โดยตรง ครอบคลุม GE, Workshop, วิชาแกน วิชาชีพบังคับ วิชาชีพเลือก `EN-135-301–348`, โครงงาน/สัมมนา และสหกิจศึกษา
# ข้อมูลตลาดงาน Jobs & Skills

หน้า `/jobs` ใช้ snapshot ผลการค้นหา JobsDB Thailand สำหรับอาชีพเป้าหมายทั้ง 17 สายจากหน้า Careers
โดยรวมประกาศซ้ำข้ามคำค้นด้วย Job ID เก็บ `searchMatches` เป็น provenance และใช้
`classifiedMatches` เป็นความสัมพันธ์อาชีพที่ผ่าน semantic classification

- `scripts/career-job-config.mjs` — คำค้นหลักและกลุ่มอาชีพย่อยที่จับคู่กับ C01–C17
- `scripts/scrape-jobsdb-careers.mjs` — เก็บรายการและรายละเอียดประกาศ พร้อม checkpoint/resume
- `data/jobsdb-careers-raw.json` — snapshot รายละเอียดและสมาชิกสายอาชีพของแต่ละงาน
- `src/jobsData.json` — snapshot หลักฉบับเต็มสำหรับสร้างข้อมูลหน้าเว็บ ไม่ถูก import เข้า bundle โดยตรง
- `scripts/build-jobs-runtime-data.mjs` — แยก snapshot เป็น index, scope ตาม C01–C17 และรายละเอียด 32 shards
- `src/jobsIndex.json` — สถิติ จำนวนงาน และ Top Skills สำหรับ first render
- `src/jobsRuntime/` — ข้อมูลรายการงานที่โหลดเมื่อเลื่อนถึงส่วนรายละเอียดหรือเลือกอาชีพ และรายละเอียดฉบับเต็มที่โหลดเมื่อกดขยาย
- `scripts/extract-career-job-skills-gemini.mjs` — สกัดทักษะและคุณสมบัติด้วย Gemini structured output พร้อม checkpoint/resume
- `scripts/classify-career-matches-gemini.mjs` — จำแนกแต่ละงานเป็น Primary/Secondary Career
  ด้วยหลักฐานจากหน้าที่และบริบทงาน พร้อมตัดผลคำค้นที่ไม่เกี่ยวข้อง

การอัปเดตข้อมูล:

1. คัดลอก `.env.example` เป็น `.env.local`
2. ใส่ `GEMINI_API_KEY` โดยไม่ commit ไฟล์ดังกล่าว
3. รัน `npm run jobs:scrape-all`
4. รัน `npm run jobs:gemini-all`
5. รัน `npm run jobs:classify-all`
6. รัน `npm run build` เพื่อตรวจผล โดย `prebuild` จะสร้าง Jobs runtime data ใหม่อัตโนมัติ

หากยังไม่มี key หน้าเว็บจะใช้ผลสกัดด้วย taxonomy เป็น fallback และแสดงวิธีสกัดไว้ในข้อมูลแต่ละงาน

ทุกสาย C01–C17 แบ่งเป็น 4 กลุ่มคำค้นย่อย รวม 68 กลุ่ม โดยรวมประกาศซ้ำด้วย Job ID
และคำนวณ Technical Skills 20 รายการจาก taxonomy เฉพาะของแต่ละสาย ส่วน Soft Skills ใช้มาตรฐานร่วม
10 รายการเพื่อให้เปรียบเทียบข้ามสายอาชีพได้

`searchMatches` เก็บเฉพาะที่มาว่าประกาศถูกพบจากคำค้นใด และไม่ใช้คำนวณจำนวนงานหรือ Skills
หน้าเว็บใช้ `classifiedMatches` เท่านั้น โดยแต่ละงานมี Primary Career ได้หนึ่งรายการ Secondary Career
ไม่เกินสองรายการ และอาจถูกตัดออกทั้งหมดหากไม่มีหลักฐานเชิงหน้าที่หรือโดเมนเพียงพอ
